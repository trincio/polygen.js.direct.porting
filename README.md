# polygen.js — Direct Porting

> **Status: pre-release alpha** — work in progress, API may change.

A direct, faithful translation of [Polygen](https://github.com/alvisespano/Polygen) (Alvise Spano', 2002) from OCaml to vanilla JavaScript.

Single file, no dependencies, browser-compatible.

## What is Polygen?

Polygen is a random text generator based on a formal grammar notation. You define a grammar and Polygen produces random sentences that conform to it. The original implementation is written in OCaml.

## This port vs. clean-room approaches

This is a **direct porting**: the internal structure mirrors the original OCaml pipeline module by module (lexer → parser → preprocessor → generator). No redesign — the generation logic is a faithful translation of the original into idiomatic JavaScript, checked byte for byte against the real OCaml binary (see *Running tests*). The few things this port adds on top of the original are listed explicitly under [Additions to the original](#additions-to-the-original).

## Usage

```html
<script src="polygen.js"></script>
<script>
  const output = Polygen.generate(`S ::= "hello" "world" ;`, { start: "S" });
  console.log(output);
</script>
```

```js
// Node.js
const Polygen = require('./polygen.js');
const output = Polygen.generate(`S ::= "hello" "world" ;`, { start: "S" });
```

### API

```js
// Compile once, generate many times (efficient)
const grammar = Polygen.compile(grammarString);
const output  = Polygen.generate(null, { grammar, start: "S" });

// All-in-one
const output = Polygen.generate(src, {
  start:  "S",           // start symbol (default: "S")
  labels: ["sg", "m"],   // active labels (default: [])
  seed:   42             // PRNG seed (deterministic if set)
});

// Several texts in a row, like the OCaml binary's `-X N` (ADDITION, see below)
const texts = Polygen.generateMany(src, { times: 5, seed: 42 });   // array of 5 strings

// Async with import resolution
const grammar = await Polygen.compileAsync(src, {
  loader: async (name) => fetch(`/grammars/${name}.grm`).then(r => r.text())
});

// Static analysis
const { errors, warnings } = Polygen.check(src);
```

## Additions to the original

Everything below is **not** a translation of the OCaml library (`polygen_lib`). It was added for use in the browser or for safety, and is kept separate so the faithful part stays easy to identify.

| Addition | What it does | Relation to the OCaml original |
|---|---|---|
| `Polygen.generateMany(src, {times: N, seed, …})` | Returns an array of `N` texts generated in a row: grammar preprocessed once, PRNG seeded once and carried on between texts, `:=` memoisation restarted for each text. | Reproduces the `-X N` option of the OCaml **command-line binary** (`polygen.ml`). The OCaml *library* only produces one text per call, so this is an addition to the library API. Compared against the real binary in the golden tests. |
| `import "file" as X` and `compileAsync` | Loads other grammars through a user-supplied loader (entry point is the imported grammar's `S`). | The OCaml source never supported import (`pre.ml` raises `Unexpected`). New feature, no OCaml reference behaviour. |
| `maxAlternatives` (default 1 000 000), `maxDepth` (default 200) | Stop cyclic or exponentially large unfold expansion and runaway recursion with a readable `PolygenError`. | Safety limits. A legitimate but extremely large grammar that OCaml could process slowly is rejected here unless the limit is raised. |
| `Polygen.check(src)` | Static analysis returning `{errors, warnings}`. | Port of `check.ml`, without `check_termination` (already disabled in the OCaml source). |

## Pipeline

```
PRNG (mulberry32)
  ↓
Lexer        (lexer.mll)
  ↓
Parser       (parser.mly)   → Absyn0
  ↓
Preprocessor (pre.ml)       → Absyn1
  ↓
Generator    (gen.ml)       → string
```

## Supported grammar features

- Terminals: `"quoted"`, bare `words`
- Non-terminals: `Capitalized`
- Alternatives: `A | B`, weighted with `+` / `-` / `++`
- Optional: `[...]`
- Labels: `label: seq`, selector `NT.label`, multi-selector `NT.(l1|l2)`
- Capitalize: `\`, Concat: `^`
- Mobile groups: `{A} {B}` (permutation)
- Unfold: `> NT`, deep unfold: `>> ... <<`
- Lock: `< NT`
- Assignment (memoized): `:=`
- Local declarations: `(Sym ::= ...; expr)`
- Repetition: `(sub)+`
- Import: `import Name as Sym` (via `compileAsync` loader)

## Running tests

```bash
node test.js                # unit tests
node tests/test.golden.js   # byte-for-byte comparison with the real OCaml binary
```

The second suite compares this port against output generated by the authentic OCaml Polygen binary (built by the GitHub Actions workflow `golden.yml` and frozen in `tests/golden.json`), on all 128 grammars of the original collection with several seeds, start symbols, labels and `-X` iterations. No OCaml installation is needed locally.
